# غرفة الرياض - الإدارة التنفيذية لدعم الأعمال
# لوحة متابعة المهام والمشاريع والاجتماعات

تطبيق ويب محلي بالكامل لإدارة المهام والمشاريع والاجتماعات، مبني بـ React + Vite + TypeScript + Tailwind CSS. يعمل التطبيق دون أي اتصال بالإنترنت ويستخدم IndexedDB لتخزين البيانات محلياً في المتصفح.

## التشغيل المحلي

```bash
npm install
npm run dev
```

للبناء للإنتاج:

```bash
npm run build
npm run preview
```

## بيانات الدخول التجريبية

| الدور | البريد الإلكتروني | كلمة المرور |
|------|-------------------|-------------|
| مدير | admin@riyadhchamber.local | Admin@12345 |
| مستخدم | user@riyadhchamber.local | User@12345 |

> هذه بيانات تطوير فقط. يمكن تغييرها من `src/data/seedData.ts`.

## الميزات

- **لوحة معلومات** تنفيذية مع بطاقات KPI ورسوم بيانية ديناميكية
- **إدارة المهام**: إضافة/تعديل/حذف، بحث، فلاتر، فرز، ترقيم صفحات
- **إدارة الاجتماعات** مع مؤشرات (اليوم/غداً/قادم/منتهي)
- **إدارة المشاريع** مع مؤشر تأخير تلقائي
- **التحليلات**: تحليل المهام والاجتماعات والمشاريع مع فلاتر
- **التقارير**: تقرير شامل وتقارير مفصلة قابلة للتصدير
- **تصدير Excel / PDF / طباعة** بترميز عربي صحيح
- **نسخ احتياطي واستيراد** للبيانات المحلية (JSON)
- **إعادة ضبط البيانات التجريبية** (للمدير فقط)
- **الوضع الفاتح / الداكن / تبعاً للنظام** مع حفظ التفضيل
- **بحث عام** في المهام والاجتماعات والمشاريع
- **مصادقة محلية** مع دورين (مدير / مستخدم) وصلاحيات مركزية
- **تصميم متجاوب** كامل (مكتوب / لوحي / جوال) مع قائمة جانبية منزلقة
- **RTL عربي** بالكامل بخط Tajawal

## قاعدة البيانات المحلية (IndexedDB)

اسم قاعدة البيانات: `riyadh_chamber_db`

المخازن (stores):
- `tasks` — المهام (المعرف: TASK-00001)
- `meetings` — الاجتماعات (المعرف: MEET-00001)
- `projects` — المشاريع (المعرف: PROJ-00001)
- `users` — المستخدمون
- `lookups` — قوائم المنسدلات
- `settings` — الإعدادات (محفوظة في LocalStorage)

تُهيأ البيانات التجريبية فقط عند أول تشغيل (إذا كانت قاعدة البيانات فارغة). لا تتم إعادة الكتابة على بيانات المستخدم عند التحديث.

## معمارية طبقة البيانات (جاهزة للترحيل المستقبلي)

```
الحالي (محلي):
  الواجهة ← طبقة الخدمات (taskService, ...) ← IndexedDB

المستقبلي (Google Sheets):
  الواجهة ← طبقة الخدمات ← Google Apps Script API ← Google Sheets
```

كل التعامل مع البيانات يتم عبر طبقة الخدمات (`src/services/`). لترحيل التطبيق إلى Google Sheets لاحقاً، استبدل التنفيذ الداخلي لكل خدمة باستدعاءات HTTP إلى Google Apps Script دون تغيير الواجهة أو الصفحات.

> مكان الترحيل المستقبلي: `src/services/taskService.ts`, `meetingService.ts`, `projectService.ts`, `userService.ts`. لا تلمس المكونات أو الصفحات.

## الصلاحيات

مركزية في `src/auth/permissions.ts`. الدوران:
- **مدير**: كل الصلاحيات بما فيها الحذف وإعادة الضبط والاستيراد
- **مستخدم**: إضافة وتعديل (بدون حذف)، عرض، تصدير، نسخ احتياطي

## تغيير القوائم (Lookups)

عدّل الملف `src/data/lookups.ts` لتغيير قيم المنسدلات (الإدارات، الأنواع، الحالات...).

## استبدال الشعار

استبدل الملف `public/logo.svg` بشعارك الخاص (يُفضل SVG مربع 64×64).

## ملاحظة أمنية

المصادقة في هذا الإصدار محلية فقط (تجزئة بسيطة من جهة العميل) ولا توفر أماناً حقيقياً ضد من يصل للمتصفح/المصدر. صُممت لتُرحل لاحقاً إلى مصادقة من جهة الخادم عبر Google Apps Script.
